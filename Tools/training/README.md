# Training and model-modification tools

These are the operational scripts that build, inspect, back up and retrain
AstroNet-v2. The core pipeline stays in `Src/`; this folder only holds the
commands you run by hand.

| Script | Purpose |
|---|---|
| `model_map.py` | Live shape/wiring map: layer shapes, parameter connections, receptive fields and a gradient-flow probe. No checkpoint needed. |
| `model_backup.py` | Minimal retrain backup: an untrained checkpoint plus 100 real crops per class (`Data/model_backup/`). Useful before adding a class or changing the architecture. |
| `phase_chain.py` | Post-acquisition chain: optional salvage → split → QC audit → full training. Waits for `Src.acquisition.streaming` unless `--dry-run` is used. |
| `salvage_crops.py` | One-time migration from the old `Data/crops/staging_quarantine/` layout into `Data/crops/staging/`. Optional: new streaming runs write staging directly. |
| `audit_crops.py` | QC statistics and visual montages for staged crops; also supports reversible quarantine/restore. |

## Typical rebuild

From the project root, with the project virtualenv:

```bash
# 1. Acquire crops (streaming deletes each source FITS after cropping)
.venv/bin/python -m Src.acquisition.streaming --per-class 300

# 2. Split + audit + train (after streaming has exited)
.venv/bin/python Tools/training/phase_chain.py --n-per-class 5000

# 3. Evaluate and export the CoreML copy
.venv/bin/python -m Src.training.evaluate
.venv/bin/python Tools/convert_to_coreml.py --force
```

`phase_chain.py` is safe to inspect first: `--dry-run` prints the exact
commands without waiting or changing files. It clears the derived
`Data/crops/{train,val,test}` folders before rebuilding them; the staging
crops and all source data are left alone.

## Model inspection and backup

```bash
# What every layer receives/emits, how many weights connect each stage,
# the receptive field, and whether every parameter receives a gradient.
.venv/bin/python Tools/training/model_map.py

# Save the empty model + a 100-crop-per-class sample (about 17 MB)
.venv/bin/python Tools/training/model_backup.py save

# Verify the backup
.venv/bin/python Tools/training/model_backup.py verify
```

`model_backup.py` reads `Data/crops/staging/`. That folder is generated by
acquisition and is not committed. If it is absent, restore it from
`Trash/datasets/crops_staging/` or re-acquire the crops first; the script
still creates the empty-model half of the backup, but the crop sample will
be empty.

## What is not here

`Trash/scripts/` now contains only the diagnostics that are not part of the
model-building path:

* `diagnose_acquisition.py` — download two FITS and inspect headers/PSF
  preprocessing when an archive breaks;
* `analyze_psf_shapes.py` — research metrics on PSF shapes.
